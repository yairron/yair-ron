# githooks

תיקיית hooks עוקבת-גרסה (לא `.git/hooks/` הרגילה, שאינה נשמרת ב-git ולא
עוברת בין שיבוטים) — כדי שההגדרה תישאר חלק מהריפו ותעבוד גם משיבוט חדש.

## הפעלה (חד-פעמית לכל שיבוט)

```
git config core.hooksPath .githooks
```

בלי הפקודה הזו הקבצים כאן קיימים בריפו אבל git לא באמת מריץ אותם.

## `pre-commit` — עדכון אוטומטי של קטלוג מסלולי האופניים

כשה-commit הנוכחי כולל שינוי (הוספה/שינוי/שינוי שם) בקובץ `.gpx` תחת
`YR1/bike/route_catalog/GPX_files/` — ה-hook מריץ אוטומטית את
`build_routes_catalog.py` (עם ה-python של `.venv` שבשורש הריפו), ומצרף
לאותו commit את הפלט המעודכן: `route_catalog/data/routes-catalog.json`,
תמונות ממוזערות חדשות/מעודכנות, וגם כל שינוי שהסקריפט עצמו עשה בתוך
`GPX_files` (כמו שינוי שם אוטומטי לקובץ שאין לו שם משמעותי).

**נקודות חשובות לדעת:**
- אם אין שום שינוי בקובץ `.gpx` ב-commit — ה-hook יוצא מיד בלי לעשות כלום
  (commit רגיל, ללא השהיה).
- אם יש שינוי כזה — ה-commit **יושהה** למשך משך הריצה של הסקריפט (כמה
  שניות עד כמה עשרות שניות, תלוי כמה קבצים חדשים יש; קבצים קיימים שלא
  השתנו מדולגים במהירות הודות למנגנון ה"תמונה כבר קיימת" בסקריפט עצמו).
- אם הסקריפט נכשל (למשל שגיאה בפענוח קובץ GPX פגום) — ה-**commit כולו
  מבוטל**, כדי שלא יכנס לריפו קטלוג לא-מעודכן/לא-עקבי. יש לתקן את הבעיה
  ולנסות שוב.
- ה-hook עושה `git add` רחב לתיקיות `route_catalog/data/` ו-`route_catalog/GPX_files/`
  כדי לתפוס כל תוצר של הריצה (כולל שינויי שם קבצים) — כלומר אם יש שם עוד
  שינויים לא-קשורים שלא התכוונת להכניס לאותו commit (בתוך אחת משתי
  התיקיות האלה בלבד), הם ייכנסו אליו גם הם. בפועל שתי התיקיות האלה
  מכילות כמעט אך ורק קבצי נתונים/תמונות שנוצרים על ידי הסקריפט, לא קוד
  שעורכים ידנית, אז הסיכון לכך נמוך.

## הרחבה עתידית

אם יתווספו הוקים נוספים (לפרויקטים אחרים בריפו) — להוסיף אותם כאן כקבצים
נפרדים (`pre-push`, hook נוסף וכו'), לא לערבב הכול בקובץ `pre-commit` אחד.
